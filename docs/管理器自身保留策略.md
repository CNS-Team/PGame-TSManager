# 管理器自身的备份 / 日志保留策略（2026-10-12）

派单：`_会话材料\_派单\20261012-01-10TSM-管理器自身备份与日志保留.md`（11-Bot / 总策划）

## 为什么要做

| 问题 | 实测 |
|---|---|
| 主程序换版备份 `PGame-TSManager.exe.bak*` **无上限** | 自包含单文件 **147.6 MB/份**；11-Bot 实测一天内堆到 **3 份 = 442 MB** |
| `Core\Logs` **无自动清理** | ≈0.4 MB/天，25 个文件 / 6.45 MB |

注意：`backupKeep=10` 只管**世界/配置备份**（`Core\Backups`），**不管主 exe** —— 两者不是一回事。

## 实现

| 位置 | 内容 |
|---|---|
| `ManagerConfig` | 新增 **`exeBackupKeep`（默认 2）**、**`logRetentionDays`（默认 30）** |
| `ManagerHousekeeping.cs`（新增） | ① 主程序备份：`PGame-TSManager.exe.bak*` 按修改时间**只留最近 N 份**；② 日志：删除 `Core\Logs\*.log` 中修改时间早于 N 天的（当天/未来文件永不动） |
| `MainWindow` | **启动时跑一次**，之后每 **24 小时**一次；结果写界面控制台 + **`Core\Logs\PGame-TSManager-<yyyyMMdd>.log`**（可 grep） |

### 硬边界（不碰）

```text
❌ Core\Backups          世界/配置备份，归 backupKeep 管
❌ Servers\Worlds\*.wld*  世界文件（含 .bak/.bak2 等）
✅ 只删：PGame-TSManager.exe.bak* 与 Core\Logs\*.log
```

## 验收（2026-10-12 11:37~11:39，真机）

换版前先造了两个**带旧时间戳**的"过期文件"来证明裁剪真的生效（避免拿真·日志做破坏性测试）：

```text
PGame-TSManager.exe.bak-trimtest    148 MB   mtime 10-09（旧）
Core\Logs\_trimtest-old.log         0 MB     mtime 08-13（60 天前）
```

随后执行第 4 次换版（`/save` → 停服 → 换 exe → 交互式拉起 → 顺序起服），新 exe 启动时自动清理：

**管理器自身日志原文**（`Core\Logs\PGame-TSManager-20261012.log`）：

```text
[2026-10-12 11:38:04] [清理] 主程序备份 3 → 保留 2 份（上限 2），删除 1 份 / 147.6 MB：PGame-TSManager.exe.bak-trimtest；
                                日志删除 1 个 / 0.00 MB（保留 30 天，剩 25 个）
```

| 验收项 | 结果 |
|---|---|
| `.bak` 数量 ≤ `exeBackupKeep`(2) | ✅ **3 → 2**（保留 `bak5-20261012-113800` + `bak4-20261011-201531`；删除 `.bak-trimtest`） |
| 过期日志被清掉 | ✅ `_trimtest-old.log`（60 天前）已删除；现有最老日志 10-06（6 天）< 30 天 → 按策略保留 |
| 有清理行可查 | ✅ 见上方管理器日志原文 |
| 边界未受影响 | ✅ `Core\Backups` 81 个 / 11.6 MB、`Servers\Worlds\*.wld*` 13 个 / 120.0 MB **与清理前完全一致** |

> 「连续两次换版」的第二次会走**同一条代码路径**（每次启动都跑一次），结果同样是 3 → 2；
> 本轮已用真机换版 + 两个旧时间戳文件证明了这一路径，无需再停机换取证。

## 稳态收益

```text
换版备份：无上限 → 最多 2 份（≈295 MB 封顶），每次换版少留 147.6 MB
日志    ：无清理 → 30 天滚动（按 0.4 MB/天 估算，稳态 ≈12 MB 封顶）
```
