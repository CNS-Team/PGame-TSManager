# 隔离沙箱（外部模拟用）配合规则 —— TSM 侧边界

> 场景：RPG / 维度 / Bot 侧需要「真机等价模拟」（例：肉山链路模拟）时，向 TSM 申请一台**隔离沙箱服**。
> 因 **TShock 进程的唯一 owner 是 TSM**，沙箱进程也由 TSM 起，规则如下。

## 一、硬规则（不可协商）

1. **进程 owner 唯一**：沙箱 TShock 由 TSM 启动/停止；申请方**不得**自己 `Start-Process`、不得 Kill、不得直接连控制台注入。
   需要发指令就走 `POST /tsm/servers/{id}/command`（或 `/tsm/servers/{id}/plugins/reload`）。
2. **不碰生产**：沙箱**不得**复用生产四服（`0/1/2/3`）的 profile、目录、端口、世界文件、数据库；
   不得在生产 runtime 目录（`Core\_runtime\<生产服>`）里起额外进程。
3. **世界用副本**：只从生产世界**复制**一份到沙箱自己的世界路径；**禁止**在生产 `.wld` 上做模拟。
4. **数据库独立**：沙箱必须指向**独立的库/表前缀**（由申请方提供连接串），禁止写生产库。
5. **禁止在生产四服上推阶段 / 改 hardmode / 换图 / 清表 / rebuild**（派单里已写明；TSM 也不会代做）。
6. **看门狗按需关**：沙箱默认**关闭自动重启**（模拟崩溃时不希望被自动拉起，便于观察）；需要开着就明说。

## 二、TSM 提供的标准沙箱形态（按需创建）

| 项 | 约定 |
|---|---|
| profile 命名 | `9.沙箱-<用途>`（例：`9.沙箱-肉山`），排在 0–3 生产服之后，一眼可辨 |
| profile 目录 | `Servers\Profiles\9.沙箱-<用途>\`（独立 `config.json` + 独立 `tshock`） |
| 世界 | `Servers\Worlds\沙箱-<用途>.wld`（从生产世界**复制**，源文件只读） |
| 端口 | 游戏 **2030** 起、REST **7890** 起（避开生产 2020–2024 / 7877–7880） |
| runtime | TSM 自动建 `Core\_runtime\9.沙箱-<用途>\`（独立沙箱，不与其他服共享） |
| 启停 | 只由 TSM 执行；申请方通过 Control API 或让我代操作 |
| 清理 | 模拟结束由 TSM 停服；世界副本与 profile 目录按需保留/删除（**删除前会先确认**） |

## 三、申请方需要提供（缺一不可）

1. 用途与预计时长（例：肉山链路模拟，约 2 小时）；
2. 需要的**插件清单**（哪些开、哪些关）；
3. **独立数据库**连接信息（库名/账号，或明确"用本地 sqlite 文件副本"）；
4. 需要的**世界基线**（默认：复制直播服当前世界）；
5. 端口是否与其它用途冲突。

## 四、TSM 侧交付物（创建后我会给出）

- 沙箱 profile 的 `serverId`（数字）、游戏端口、REST 端口与 `restTokenAlias`；
- `GET /tsm/servers` 里该项的实时状态（`state/pid/rebuilding`）；
- 沙箱的存档/日志位置（`Core\Logs\9.沙箱-<用途>-yyyyMMdd.log`）；
- 模拟结束后的一份「结果 + 清理情况」回执，并上报。
