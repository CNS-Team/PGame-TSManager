# 本机网络 / 代理口径（做 GitHub 相关操作前先看这里）

> 来源：11-Bot 于 2026-10-11 更正 —— **我此前记的 `127.0.0.1:7897` 已失效**。

## 一句话

```text
github.com 直连会超时 → 必须走 Clash 代理：http://127.0.0.1:7890
（旧端口 7897 已失效，不要再写进任何脚本/文档）
```

## 实测情况（TSM 侧）

| 目标 | 结果 |
|---|---|
| `github.com`（网页 / clone / 下载） | **直连超时** → 需要代理 `http://127.0.0.1:7890` |
| `api.github.com`（公开 API 读） | 2026-10-11 实测**可直连**（读 releases / artifacts / runs 全部成功，未设代理） |
| `objects.githubusercontent.com` 等下载域 | 2026-10-11 实测可用（`maintenance\tools\Build-Local.ps1` 里 `Prepare-TShockRuntime.ps1` 拉官方 TShock 运行时成功，23 秒跑完） |

⇒ 结论：**API/下载域目前能直连，但 `github.com` 本体不行**。写脚本时不要假设"全都直连"，
需要访问 `github.com` 本体（网页、git clone over HTTPS、Release 页面）时统一加：

```powershell
$env:HTTPS_PROXY = 'http://127.0.0.1:7890'   # 需要时临时设；用完可 Remove-Item Env:\HTTPS_PROXY
git -c http.proxy=http://127.0.0.1:7890 clone https://github.com/<owner>/<repo>.git
```

> 我们没有 `gh` CLI，也没有 PAT（本机 `GH_TOKEN`/`GITHUB_TOKEN` 均未设置），
> 所以一切**写操作**（删 artifacts / Release）都走「推送触发 `.github/workflows/prune.yml`」这条路（用仓库内置 `GITHUB_TOKEN`），
> 不需要本地凭据；公开 API 的**读**操作可直连。
