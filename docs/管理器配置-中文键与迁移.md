# 管理器自身 config.json：中文键 + 旧键自动迁移（2026-10-12）

用户要求：**TSM 根目录的 `config.json` 也要汉化**（此前只有 TShock 的 `tshock\config.json` 汉化）。

## 一句话

```text
<TSM 根>\config.json   ← 管理器自身配置，2026-10-12 起全部使用**中文键**；
                          老部署的英文键在**首次启动时自动迁移**（原文件留 .bak-<时间戳>），不会再回退。
```

## 迁移机制（为什么老部署不会丢配置）

`ManagerConfig.LoadConfig()`：

1. 读原始文本 → `MigrateLegacyKeys()` 把旧英文键改写成中文键（**幂等**：已是中文就原样返回）；
2. 反序列化后**全量补全**：若磁盘上的键集合 ≠ 当前版本的键集合（缺新字段 / 有已删字段），
   就把**当前版本所有字段**（含所有新增开关）以中文键整体写回 —— 于是 `config.json` 本身就是
   「当前版本全部可调项的中文清单」，用户能直接看到每个开关，不会出现"新加的键藏在代码里、文件里看不到"；
3. 上述任一种情况发生改写前，都把**原文件**备份成 `config.json.bak-<yyyyMMdd-HHmmss>`。

> ⚠ 没有这一步的话，改了 `[JsonProperty]` 之后反序列化会**全部落默认值** —— 其中
> **`控制API令牌`（旧 `controlApiToken`）会丢**，Control API / Bot / FixTools 全依赖它。

自检命令（无界面、令牌打码）：`PGame-TSManager.exe --dumpconfig` → 生成 `configdump.txt`，可用来对比迁移前后取值。

> 实测（远程 2026-10-12）：`47 键（英文）→ 47 键（中文，取值不变）→ 55 键（中文全量）`，
> 令牌 64 位、`服务器列表` 4 条、`外部进程` 2 条（`进程名=流光维度.启动器`、`看门狗=none`）全部保持不变。
> `config.json.bak-*` 每份约 7 KB，不在"主程序备份/日志"清理范围内（体量可忽略，需要时可手动删）。

> ⚠ **务必分清两层**：
> ```text
> ① 配置文件 <TSM 根>\config.json          → 键名 = 中文（本页对照表）
> ② Control API 的 HTTP 响应（/tsm/external 等）→ 字段名 = 英文，**契约不变**
> ```
> 原因：`ExternalProcessRuntime.Snapshot()` 返回的是**匿名对象**（字段名写死在代码里），
> `[JsonProperty]` 只作用于**序列化到配置文件**那条路径。
>
> 实测（2026-10-12 17:45，远程）：`GET /tsm/external` 返回
> `id / name / enabled / kind / state / pid / processName / healthMode / healthOk / healthUrl / healthPorts / logDir / logActive / watchdog / autoRestart / at`
> —— **全部仍是英文**；维度 `running`(pid 12776, healthOk=true)、Bot `running`(pid 13608, logActive=true)。
>
> 读 `config.json` 的脚本请按中文键取值，或同时兼容旧键（TSM 侧 4 个运维脚本已改成"中文优先、英文兜底"）。
