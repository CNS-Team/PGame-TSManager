# 看门狗提示口径：控制台 vs 日志（2026-10-13 定案）

**规则**：看门狗的**例行说明类**提示只进日志文件、不刷控制台面板；
**异常 / 需人工知悉类**提示保留在控制台。
日志里始终有全部消息（`Core\Logs\<服>-<日期>.log`，带 `[HH:mm:ss]` 时间戳），排查照常。

**今后新增看门狗提示一律先分级**：例行 → `AddTextLogOnly(text)`；异常 → `AddText(text)`。

## 只进日志（AddTextLogOnly，不刷控制台）

| 消息 | 触发点 |
|---|---|
| `[看门狗] 检测到维护命令，暂停健康检查 N 秒` | `ArmWatchdogSuppression`（每次 `/save`、`/hr`、`/reload`、`/world` 都触发——最高频噪音源） |
| `[看门狗] 这是手动停止，不自动重启` / `[看门狗] 这是维护/换图操作期间退出，不自动重启` | 进程退出时（受控停止） |
| `[看门狗] 服务器正常退出（退出码 0），不自动重启` | 进程退出时 |
| `[看门狗] 发现同沙箱残留进程 PID x，正在清理` / `[看门狗] 已清理残留服务端，等待文件句柄释放` | 重启前残留清理 |

## 保留在控制台（AddText）

| 消息 | 理由 |
|---|---|
| `[看门狗] {title}：{detail}`（进程存活但已不可用 → 死服重启） | 异常，即将强制重启 |
| `[看门狗] 已关闭，不自动重启` | 异常退出 + 看门狗被关，需知悉 |
| `[看门狗] 连续自动重启已达上限 N 次，停止重启（请人工检查）` | 需人工处理 |
| `[看门狗] {exitInfo}，N 秒后自动重启（第 x/y 次）` / `已发起第 x/y 次重启` / `重启失败：…` | 异常恢复链路 |
| `[看门狗] 世界缺失，已启用自动建图保护 N 秒（autocreate=x）` | 异常（世界缺失） |

## 实现

- 通道：`ServerContainer.AddTextLogOnly(text)` → 只调 `WriteToFile`（`FileLogGate` 加锁，任意线程可调），不走 UI `_para`。
- 注意：被静默的行**仍在日志文件里**；只是控制台面板不显示。
- 已核对无副作用耦合：`AppendText` 里的 `IsWatchdogManualStopLine` / `IsWatchdogMaintenanceLine` 匹配的是「执行了 /xxx」类 TShock 回显，与上表各行不重叠；被静默行的状态（抑制计时、计数清零等）均在其输出之前已置位。
